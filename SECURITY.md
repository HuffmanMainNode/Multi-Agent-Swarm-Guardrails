# Security Policy

Report vulnerabilities in the reference evaluator, contract catalog, evidence verification, parsing, supply chain, or CI. Do not publish an exploitable issue before maintainers can assess it. Use GitHub private vulnerability reporting if enabled; otherwise contact the maintainer through a verified channel on the GitHub profile.

Include affected commit/version, environment, exact reproduction, expected and observed behavior, impact, prerequisites, and mitigation if known. Never send secrets, customer data, private keys, or third-party exploit payloads.

This project is experimental. Do not rely on it as the sole control for production or high-impact systems. No response-time SLA is promised. Pin a reviewed commit or release rather than an unpinned branch.

Good-faith research that avoids privacy violations, data destruction, disruption, persistence, credential theft, and harm to third parties is welcome. Stop when you encounter systems outside your authorization.
